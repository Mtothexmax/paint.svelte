The pointer is necessarily on the header when you click it, so the submenu was

Scope: MenuBar.svelte is the ONLY place with this pattern — ContextMenu.svelte

-- DONE (Motion Blur: angle slider -> rotation dial) --
Request:
  "und angle picker bei motion blur"

motionBlur.ts: `angle` was a plain slider (0..360) -> now `kind: 'angle'`, same
0..360 range (a full turn, so the dial wraps).

The range change ALONE would have been wrong. The dial reads 0 = up, clockwise
(AnglePicker convention), but the shader's theta is measured from the +x axis:
  vec2 endOffset = vec2(-uDistance * cos(uAngle), uDistance * sin(uAngle)) * texel;
in UV space where y points DOWN. So shader theta = 0 points LEFT and grows
counter-clockwise on screen — dial 0 would have given a HORIZONTAL blur. Fixed by
re-anchoring in filter():
  uAngle: { value: ((90 - settings.angle) * Math.PI) / 180, type: 'f32' }
Derivation: the streak must run along the dial direction (sin D, -cos D). With
centered = 0 the shader samples v + t*e, so a dot at P smears onto [P, P - e] —
it extends along -e. Setting -e = (sin D, -cos D) with e = (-cos t, sin t) gives
t = 90 - D. Hence 0 -> vertical, 90 -> horizontal.
This changes how the default 25 renders (it used to mean shader theta 25,
left-ish) — which is the point: the dial now points where the streak runs.
