# 2026-09-10

## Fixed: GitHub Pages console error `Cannot read properties of undefined (reading 'default')`

**Symptom** — on the static export in `docs/` (built by `export.ps1`, served from
`/paint.svelte`) the console showed
`TypeError: Cannot read properties of undefined (reading 'default')` in
`_app/immutable/nodes/2.*.js`, plus a `favicon.ico` 404. App booted but the error was
caught by SvelteKit's `handleError`.

**Root cause — import cycle in the effects auto-discovery.**
`src/lib/effects/registry.ts` used

```ts
const modules = import.meta.glob<{ default?: unknown }>('./**/*.ts', { eager: true });
```

which **also matched `./index.ts`** — the public barrel that re-exports `./registry` itself.
So registry → index → registry. In dev (unbundled ESM) Vite resolves that lazily and it is
harmless; in the production bundle rolldown has to initialise the barrel's namespace object
*after* the registry body (the namespace var for `index.ts` is emitted ~900 chars below the
glob map), so the map entry is `undefined` and `mod.default` throws at module-eval time.

**Fix**
- `registry.ts` now globs only the effect folders
  (`['./adjustments/*.ts', './blurs/*.ts', './distort/*.ts', './noise/*.ts', './object/*.ts',
  './photo/*.ts', './render/*.ts', './stylize/*.ts']`) so infra files (index/types/apply/
  shaders/registry) can never re-enter the cycle. Array form works in dev *and* build.
- `mod?.default` as a belt-and-braces guard.
- Added a real favicon: copied `src/lib/assets/favicon.svg` → `static/favicon.svg` and
  `<link rel="icon" href="%sveltekit.assets%/favicon.svg" type="image/svg+xml"/>` in
  `src/app.html` (kills the `/favicon.ico` 404).

Also finished the todo3 step-2 leftover: `MoveEngine.unwarpPoint()` (inverse homography via
`invertHomography`, falls back to `p - offset`) — the file had been left referencing a
method that did not exist.

**Verification** — `npx tsc --noEmit` clean; `npm run check` → 0 errors / 53 warnings
(pre-existing); rebuilt `docs/`, served it locally under `/paint.svelte` in headless Chrome:
zero console errors, zero 4xx, Effects menu fully populated (Blurs/Distort/Noise/Photo/
Render/Stylize/Object). Dev server also clean.

### Reusable recipe: smoke-testing the static export on Windows
`agent-browser` is unavailable on Windows, but `puppeteer-core` (already in node_modules)
drives the installed Chrome just fine:

1. tiny node http server mapping `/paint.svelte/*` → `docs/*`
2. `puppeteer.launch({ executablePath: 'C:\\Program Files\\Google\\Chrome\\Application\\chrome.exe',
   headless: 'new', args: ['--no-sandbox','--enable-unsafe-swiftshader'] })`
3. collect `console` / `pageerror` / `response>=400`, `goto(..., {waitUntil:'networkidle2'})`.

To find *which* glob entry was undefined: `page.evaluateOnNewDocument` wrapping
`Object.entries` to `console.warn` any `v === undefined` key + stack. That pinpointed
`./index.ts` immediately.

### Gotchas
- `export.ps1` deletes `build/` and restores `vite.config.ts` in a `finally` block; if the
  build fails you only see "Cleaned up". Run `npm run build` manually with the export config
  to see the real error. A stale `.svelte-kit` can make the first `vite build` fail with
  `ERR_MODULE_NOT_FOUND …/output/server/internal.js` — a second run succeeds.
- bash heredocs mangle `[/\\]` in the config; use the Write tool for `vite.config.ts`.
- `rm -rf <dir>` is blocked by the safe-delete hook on this machine; `rm -f` on individual
  files works.

# 2026-09-10 (later) — Distort bugs (bug 1 + bug 2)

## Reported
User: *"the distort does not work on the first selecting it in the modes, only when i click on it the dragger points appear, also if an angle goes inward weird math happens and it looks like the image explodes outside of its selection area"*

## Bug 1 — draggers only appeared after the first click
- `transformHandleAt()` + `distortCornerPoints()` both hit-tested `moveEngine?.warpCorners`,
  which is `null` until `MoveEngine.begin()` lifts the pixels.
- Fix in `EditorCanvas.svelte`: new `distortQuadPoints()` falls back to `handleBounds` (the
  active selection rectangle) so the four corner draggers live on the SELECTION box immediately.
- `moveToolMode.subscribe(...)` was just `moveEngine?.setMode(v)` — did not bump
  `transformRevision`, so switching to Distort never redrew the overlay. Now also calls
  `syncTransformUi()`.

## Bug 2 — inward corner drag exploded the warp
- Root cause: the selection MASK was being warped as a DOC-sized surface pushed through the
  selection-quad homography. The document corners (far outside the source quad) cross the
  homography's vanishing line after only a few pixels of drag → mesh explodes.
- Fix:
  1. `MoveEngine.warpMask(dest, blend)` crops the mask to the selection bounds first, then
     warps that crop with the quad corners. Source and corner-pin quad are now the same
     size, so the homography is always finite for a convex quad.
  2. Dropped `homographyKeepsRectFinite` from the safety check (it was over-restrictive:
     a 15% inward pull on a small selection inside an 800x600 doc was rejected — see
     `scripts/check-distort-clamp.mjs`).
  3. `quadIsSafe` now only requires `isConvexQuad` + `|quadArea| >= 4`. `safeQuad` binary
     searches the drag back to the last safe pose. Removed `homographyKeepsRectFinite` export.

## Verification (headless Chrome on the running dev server)
- Drawn 1920x1080 doc, rect selection, switched Move -> Distort -> 4 draggers visible at the
  selection corners BEFORE any click.
- Dragged NW all the way to SE: dragger stops at the convexity limit (~50% along the
  diagonal), 3 other corners stay put, no explosion.
- Switched to Rotate: 3 axis rings render.
- Zero console errors. tsc clean, svelte-check 0 errors / 53 warnings.

## Collateral: filter-chain support in the effects system
- `EffectDefinition.filter` was typed as `() => Filter`. `median.ts` (WIP from a previous
  interrupted session) needed a 2-pass separable median (horizontal + vertical pass) and
  couldn't compile.
- Widened: `EffectFilterChain = Filter | Filter[]`, `asFilterChain()`. `applyFilterSwap`,
  the `EffectContext.applyFilterSwap`, the preview path
  (`setActiveLayerFilter` / `setActiveLayerFilterPreview`), `DocScene.renderEffectChain` and
  `layerEffectsService` all handle the chain (Pixi's `sprite.filters` runs an array
  sequentially). Added a shared `renderFilterChain` helper to `effects/apply.ts` for the
  ping-pong case.
- Also fixed `vec2` -> `vec2<f32>` in `median.ts` uniform type strings (Pixi v8 GLSL3 type).
