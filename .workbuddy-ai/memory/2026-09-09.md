# 2026-09-09

## Fixed: effect preview was not scoped to the selection (Clouds)

**Root cause** — `DocScene.setActiveLayerFilter` attached the effect filter directly to the
active layer sprite. Pixi v8's `FilterSystem` clips filter bounds to the viewport
(`bounds.fitBounds(0, viewport)`), and the shader's `vTextureCoord` is normalised over that
CLIPPED region (`vTextureCoord = aPosition * uOutputFrame.zw * uInputSize.zw`). Consequences:

- Procedural/render effects (Clouds, Flames, Turbulence, Julia/Mandelbrot) generated their
  pattern from the visible window, so the pattern shifted with every zoom/pan and never
  matched the applied result.
- The second "selection scope" filter sampled the doc-sized `uMask` / `uOriginal` with the
  same clipped `vTextureCoord`, so the effect was mis-scoped (not applied to the selection).

**Fix** — preview is now rendered OFF-SCREEN into pooled doc-sized render textures (the same
pass `applyFilterSwap` uses) and the result is swapped onto the layer sprite
(`sprite.texture = ...`). Preview is now pixel-identical to Apply and independent of zoom/pan.
Selection scoping reuses the `holder + maskSprite` construction from `render/blitMaskedInto`.
Removed `SELECTION_SCOPE_FRAGMENT`, `GlProgram`/`defaultFilterVert` imports from DocScene.
Bookkeeping: `previewLayerId` / `previewSurfaceId` so a layer or surface swap drops a stale
preview; `restorePreview()` re-attaches it after `rebuildLayers`.

Also: `clouds.ts` `isNoop` was `contrast <= 0`, which wrongly disabled Apply even though
contrast 0 still renders clouds → now `() => false` (consistent with Flames).

## Implemented: Paint.NET-style Adjustments menu (12 registered + 1 instant)

**Architecture** — all tonal adjustments live under `src/lib/effects/adjustments/` and are
auto-registered into the effect system. The `Adjustments` group is lifted OUT of the Effects
submenus (via `ADJUSTMENTS_MENU` export in the registry) and surfaced as its own top-level
menu in `menuService.ts`, alphabetically sorted.

**Effect definitions created:**
- `autoLevel` — per-channel histogram analysis (CPU readback, cached by surfaceId) + linear
  stretch via `ColorMatrixFilter`.
- `blackAndWhite` — Rec. 601 luminance matrix.
- `brightCont` — Pinta intensity-based algorithm ported to a GLSL shader with unpremultiply.
- `curves` — Catmull-Rom spline LUT baked into a 256×1 RGBA texture, master+per-channel.
  Custom `CurvesDialog.svelte` with SVG editor, draggable control points, channel tabs.
- `exposure` — `v * 2^EV` shader.
- `highlightsShadows` — luminance-masked lift/push shader.
- `hueSat` — `ColorMatrixFilter` with Paint.NET ranges (Hue -180..180, Sat/Light 0..200).
- `invertAlpha` — alpha-row flip via `ColorMatrixFilter`.
- `levels` — input black/white/gamma + output black/white shader.
- `posterize` — `floor(v*(n-1)+0.5)/(n-1)` shader.
- `sepia` — classic sepia matrix.
- `threshold` — luminance hard threshold shader.

**Infrastructure changes:**
- `EffectDefinition.dialog?: string` — custom dialog override (used by Curves).
- `GlUniform` extended with `vec3<f32>` and `vec4<f32>` for level uniforms.
- `ADJUST_GLSL` shared helper in `shaders.ts` handles premultiplied↔straight round-trip.
- Removed legacy `HueSatDialog`, `BrightContDialog`, and the CPU-based
  `brightnessContrastActiveLayer`/`hueSaturationActiveLayer` helpers from `render/effects.ts`.
- `Invert Colors` kept as an instant command (`adjustments.invertColors`) with Ctrl+Shift+I.

## Implemented: Object effects + live Layer Effects

**Object effect definitions** (`src/lib/effects/object/`):
- `outline` — alpha-neighbor search in a square kernel; transparent pixels adjacent to
  opaque pixels are coloured with the outline colour.
- `shadow` — offsets the sampling position, box-blurs the alpha, and composites the
  coloured shadow behind the original.
- `feather` — box-blur of the alpha channel only (smooths hard edges / removes white
  outline from rough selections).
- `bevel` — samples the alpha gradient and adds highlight/shadow based on a light angle.

All object effects are available both as one-shot `Effects > Object` menu items AND as
live layer effects.

**Layer effects architecture:**
- `Layer.effects?: LayerEffect[]` added to the core Layer model.
- `DocScene` renders effects off-screen per layer into cached `RenderTexture`s
  (`layerEffectTextures` map). The sprite shows the cached texture instead of the raw
  surface — non-destructive, updates live when settings change.
- `DocScene.refreshLayerEffects(layerId)` re-renders the effect chain for one layer.
- `EditorRenderer.refreshLayerEffects(layerId)` proxies to the active scene.

**Services:**
- `layerEffectsService.ts` — `addLayerEffect`, `removeLayerEffect`, `toggleLayerEffect`,
  `updateLayerEffectSettings`, `bakeLayerEffects` ("Render Effects to Layer").
- Baking renders the filter chain into a new surface, swaps the layer's `surfaceId`,
  clears `effects`, and records one undoable history entry.

**UI:**
- `LayerEffectDialog.svelte` — add/edit dialog (similar to EffectDialog but updates the
  layer model instead of swapping the surface). Preview temporarily pushes a transient
  effect and removes it on cancel.
- Layers panel context menu: "Add Layer Effect" (flat list of object effects), toggle/edit/
  remove per effect, "Render Effects to Layer".
- `fx` badge on layer rows when active effects are present.
- Text → raster conversion preserves effects (`convertTextToRaster`).

**Verification**

`npx svelte-check --threshold error` → 0 errors; `npm run build` → OK.

## Fixed: editor crashed on load ("Unknown surface")

**Symptom** — `SurfaceStore.getTexture` threw `Unknown surface: sfc-…` during
`DocScene.rebuildLayers` → `new DocScene`, blanking the whole editor at startup. The stack
attributed it to `EditorRenderer.init`, but it actually fires from `restoreSession` →
`documentRegistry.open` → `addDoc` → `new DocScene` (V8 attributes the continuation to the
promise that resolved it, `init`'s `resolveReady`). Root cause: a renderer/SurfaceStore
mismatch after hot-reload of render-layer modules — `documentRegistry` kept docs whose
`layer.surfaceId` pointed at the OLD store, which the fresh renderer no longer owns.

**Defensive fixes (so a missing surface never blanks the app):**
- `DocScene.resolveLayerTexture()` — returns the effect texture or base surface; if the base
  surface is missing it creates a transparent placeholder, reassigns `layer.surfaceId`, and
  logs. Used by `rebuildLayers`.
- `DocScene.layerEffectTexture()` wrapped in try/catch (return null) so a failing effect
  filter can't crash scene construction.
- `EditorRenderer.addDoc()` wrapped in try/catch; one bad doc won't abort the others.
- `restoreSession()` is now idempotent: bails if `documentRegistry.count > 0` (handles HMR
  re-entry / duplicate restore). `buildDoc` no longer sinks the whole doc on one unreadable
  layer bitmap — it falls back to an empty surface per layer.

**User-facing note** — a hard reload (not just HMR) is the real cure for the stale mismatch;
the fixes make the app load regardless.

## Fixed: Add Noise filter (diagonal banding + GLSL `uvec2` compile error)

User reported non-uniform noise with a diagonal artifact (bottom-left → top-right, biased to
bottom-right). They asked Gemini, which introduced a GLSL compile error:
`ERROR: 0:22: 'uvec2' : syntax error`.

**Root causes**
- Pixi v8's `FilterSystem` compiles custom filters as **GLSL ES 1.00**, where `uvec2`/`uvec3`/
  `uint`/`ivec2` and the `^` operator are syntax errors (Gemini's integer-bitwise hash).
- The diagonal banding is the classic `sin(dot(p, vec2(127.1, 311.7))) * 43758` hash: that
  dot-product is itself a *diagonal* function, so its noise correlates along that direction and
  bands — amplified at high resolutions by `sin()` float-precision loss.

**Fix** (`src/lib/effects/noise/addNoise.ts`) — rewrote the hash with Dave Hoskins' "hash
without sine" (pure `float`/`fract`/`dot`, decorrelated via `.yzx` swizzles), driven by
**integer pixel coordinates** (`floor(vTextureCoord * uInputSize.xy)`) so each pixel gets one
independent, uniformly-distributed value. Seed shifts the lattice (`px + vec2(uSeed, …)`).
Also fixed premultiplied-alpha handling: un-premultiply → add noise in straight space →
re-premultiply on write (avoids hue drift on semi-transparent pixels). Now GLSL ES 1.00-safe
and diagonal-free.

**Verification** — `npx svelte-check --threshold error` → 0 errors; `npm run build` → OK.
(Note: GLSL shader correctness only fully verifies at GPU compile time in the browser.)

## Added reusable XY pad + Angle dial components (FL Studio style)

User wanted mouse-friendly replacements for x/y sliders and angle sliders: a square pad
with a draggable point + X/Y number fields each with a reset, and a circular angle dial with
a draggable handle + reset. Built as reusable Svelte 5 components in `src/lib/components/common/`:

- `XYPicker.svelte` (+`.css`) — `value: {x,y}` (bindable), props minX/maxX/minY/maxY/step/default
  (default range -100..100, top=maxY). Click/drag on pad + editable X/Y fields + per-axis reset.
  Arrow-key nudge on fields.
- `AnglePicker.svelte` (+`.css`) — `value: number` degrees (bindable), 0°=up, clockwise, range
  default 0..360 (wraps). Draggable handle + number field + reset.
- `XyParam.svelte` — bridges an `xy` EffectParam to XYPicker; owns the `{x,y}` state and writes
  two numeric settings keys `${key}X` / `${key}Y` (snippet bodies can't hold `let`/`$state`, so a
  child component is required for per-instance state).

**Effect system integration** — `EffectParam.kind` now allows `'xy'` and `'angle'` (types.ts).
`EffectDialog.svelte` and `LayerEffectDialog.svelte` render them (angle → `bind:value`; xy →
`<XyParam>`). `bevel.ts`'s "Light Angle" switched to `kind: 'angle'` as the first user.

**Convention for `xy`**: effect reads `settings[`${key}X`]` and `settings[`${key}Y`]` as two
separate numbers; `default`/`defaultY` and ranges via `minX/maxX/minY/maxY`/`step`/`stepY`.

**Verification** — `npx svelte-check --threshold error` → 0 errors; `npm run build` → OK.

**Gotcha** — snippets (`{#snippet}`) are markup-only; you cannot `let`/`$state` inside a snippet
body. For per-instance reactive state in a generated list, use a child component (XyParam). Also
a Svelte `<script>` parse error makes the module report "no default export" downstream — fix the
template, not the import site.

## Fixed: Adjustments menu icons not shown

**Symptom** — Auto-Level / Black and White / Sepia / Invert Alpha (the requested emoji icons)
didn't render in the top **Adjustments** menu; Brightness/Contrast showed the ☀️ emoji
("weirdly").

**Root cause** — `MenuBar.svelte`'s `COMMAND_ICONS` only mapped `effects.${id}` → `e.icon`.
The 4 instant (no-param) adjustments run via dedicated `adjustments.*` commands
(`adjustments.autoLevel`, `adjustments.blackAndWhite`, …) which had **no icon entry**,
so `iconOf()` returned `''`. Brightness/Contrast fell into the `effects.brightCont` → ☀️
fallback (the emoji that looked odd).

**Fix** — `MenuBar.svelte` now also derives `adjustments.${id}` → `e.icon` from
`adjustmentEffects` (kept `adjustments.hueSat` 🌈 / `adjustments.invertColors` 🔁 explicit
so they still win). Brightness/Contrast now uses its clean Material-Symbols SVG for both
`adjustments.brightCont` and `effects.brightCont` (`COMMAND_SVG_ICONS`), replacing the
☀️ emoji. Icons now stay in sync with the effect definitions' `icon` field.

**Verification** — `npx svelte-check --threshold error` → 0 errors; `npm run build` → OK.

## Refactor: Move-Pixels tool split into move / rotate / distort sub-modes (todo3, step 1)

**What** — the "Move Selected Pixels" tool had its move AND transform maths inside
`src/lib/render/MoveEngine.ts` plus a boolean `moveDistort` store. Step 1 (refactor +
placeholders only, no new visuals yet):

- New `src/lib/core/toolMode.ts`: `MoveToolMode = 'move' | 'rotate' | 'distort'` +
  `MOVE_TOOL_MODES` / `MOVE_TOOL_MODE_LABELS`. Lives in core so state (ui.ts) and render
  can share it without importing each other.
- New `src/lib/render/move/` package (pure gesture maths, no renderer access):
  - `types.ts` — `TransformHandle`, `TransformState`, `TransformGesture`, `beginGesture`,
    `clampScale`, `isScaleHandle` / `isTranslationHandle`.
  - `moveLogic.ts` — translation (`beginMove` / `moveTo` / `nudge` / `sameOffset`).
  - `rotateLogic.ts` — the OLD "transform" logic renamed: rotate, scale-from-anchor,
    pivot drag, `offsetForPivot`, `inverseTransformPoint`, `snapRotation`, `pivotTo`.
  - `distortLogic.ts` — PLACEHOLDER for the 4-corner warp: `DistortQuad`, `cornerAt`,
    `moveCorner`, a working `computeHomography` / `applyHomography` (not wired yet), and
    the legacy shear `distortTo` so the shipped Distort option keeps working.
  - `index.ts` — barrel.
- `MoveEngine` now only owns the session (lift / float / drop / commit / hit-test) and
  delegates: `setMode()`, `moveGesture` / `transformGesture`, `currentState()`,
  `applyState()`; `setDistortMode()` is gone.
- `src/lib/state/ui.ts`: `moveDistort: boolean` → `moveToolMode: MoveToolMode`; wired in
  `EditorCanvas.svelte` (nudge + subscription) and `pointerDown.ts`.
- `ToolOptions.svelte`: the 2 buttons became 3 (⤢ Move / ⟳ Rotate / ◩ Distort) generated
  from `MOVE_TOOL_MODES`. Rotate = old Transform renamed; Distort still shears for now.

**Gotcha** — `startMoveDrag()` calls `beginTransform('move', …)` but the pointermove path
uses `moveTo()` (no `transformHandle` set), so `beginTransform` must also arm the
`moveGesture`; otherwise that drag silently does nothing.

**Behaviour** — intentionally unchanged: move/rotate both still scale from the grips,
distort still shears. The Blender-style 3 axis rings (rotate) and the 4 independent corner
draggers + projective warp (distort) are step 2.

**Verification** — `npm run check` → only the 2 pre-existing `EffectPanel.svelte`
`param.min/max` errors; nothing new. Dev server (port 5173) hot-reloads cleanly.
